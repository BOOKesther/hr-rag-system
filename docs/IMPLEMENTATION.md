# MVP 实现与边界

依据 `requirements/PRD.md`，实现本地 FastAPI + Gradio 单进程演示。OCR 按 PRD 第 13 节澄清不纳入 MVP。

## 已实现

- DOCX/PPTX/PDF 批量上传、大小/扩展名/签名/压缩包路径/宏校验；UUID 原件存储。
- 后台串行任务、阶段事件、耗时/页数/字段数/知识块数、错误提示与重试；进程重启后中断任务可重新处理。
- DOCX 段落、表格与文本框；PPTX 文本形状、分组、表格与坐标；PDF 文本、表格和页面坐标。
- 独立布局元素、按章节与日期归并的语义块、知识块、原始证据映射；解析 JSON 和知识 JSON 使用 Pydantic 校验。
- 规则抽取姓名、城市、岗位、显式工作年限、学历和联系方式；不确定字段保留空值。
- 文件 SHA-256 与保序归一化内容指纹拒收；电话/邮箱哈希匹配候选人，无联系方式时要求姓名与教育记录共同匹配。
- SQLite WAL 事务更新活动版本，旧版 FTS/向量记录移除；模型失败不会切换活动版本。
- 干净知识投影不包含解析元数据，移除联系方式、年龄、性别；识别的家属/紧急联系内容隔离。
- FTS5 中文分词 BM25、sqlite-vec 向量、城市/年限/学历/明确技术词过滤、候选人级 RRF；检索日志与证据链接。
- LlamaIndex `TextNode`、`QueryBundle`、`NodeWithScore` 节点与上下文编排；HTTP 兼容模型适配器。
- 页面包含人才检索、上传处理、档案库、结构化字段、来源/快照、解析 JSON 和检索调试。
- PDF 真实页面快照；LibreOffice 可选 Office 渲染；图片提取和候选头像 PNG/Base64。

## 明确限制

1. 默认 `local-hash` 是可复现的词项哈希向量，不是真实语义模型。默认回答是证据摘录。配置兼容 embedding/chat API 后启用模型；此次未使用真实云模型凭据验证。
2. 路由采用可解释规则，不包含 LLM 路由 Agent、视觉理解、OCR 或重排模型。扫描件明确失败，不作为空档案入库。
3. 未安装 LibreOffice 时 Office 文档缺少真实快照，任务为 `partial_success`。DOCX XML 不能确定真实页码；返回 `null`，保留元素和原件引用，不伪造页码。
4. 复杂双栏与跨页条目仅采用原生顺序、形状坐标及标题启发式；图标标题推断、完整版式图和复杂合并表格语义恢复尚不具备完整 PRD 验收能力。DOCX 记录纵向合并标记，不能声称全部复杂表格已还原。
5. 头像使用尺寸/比例候选规则，不是人脸识别；小图或不支持的媒体可能未识别。默认界面隐藏头像。
6. 工作、教育、项目保留章节条目和证据，尚未完整拆成每个公司/职位/日期的结构化字段。自然语言过滤限明确城市、数字年限、学历及列出的技术词，不等于任意逻辑表达式理解。
7. 跨格式指纹保留事实顺序，忽略格式空白与标点；阅读顺序不同的同内容文件可能接受为新版本，不会单凭词袋近似错误拒收。
8. Embedding 型号/维度变更会拒绝复用旧索引。使用新的 `HR_DATA_DIR` 重导入形成新库，旧库保留；未实现在线多版本索引管理。
9. 失败重试重新执行解析；活动版本重试仅补齐快照。没有分阶段缓存恢复、人工归并和人工修订。
10. 本地演示没有认证、权限和数据加密。仅绑定回环地址；原文件下载包含完整信息。不要直接暴露到公网。

这些限制不影响上传 → 档案入库 → 自然语言检索 → 证据复核的演示闭环，但不能把本次交付宣称为 PRD 全部增强项已验收。

## 验证

`python -m pytest -q` 覆盖全部合成样本、重复与版本、索引清理、模型失败回滚、敏感信息、扫描 PDF、恶意路径及 HTTP 上传。

`python -m scripts.verify_demo` 首次运行导入 12 个样本，输出三条 PRD 查询及不存在条件查询，并保存 `data/verification.json`。

PRD 示例“上海 5 年以上 SaaS 产品经验”必须执行上海硬过滤。林若溪的原文现居杭州，因此不会出现在此查询中；搜索“SaaS 客户成功 5 年以上”可召回她。不能为满足示例名单忽略实际城市条件。
